# Research basis: the drafter and its training

This note lists every design element of the drafter (`python/woodcock/drafter.py`),
of its training (`python/woodcock/train.py`, `python/woodcock/data.py`) and of the
decoding loop that uses it (`python/woodcock/spec.py`, `policies.py`, `sampling.py`),
and says for each one where it comes from:

* **[pub]** — described in a public paper; the arXiv identifier and section are
  given. Section numbers were checked against the arXiv HTML versions on 2026-10-22.
* **[pub, reading]** — the paper states the idea but not the exact wiring; the
  wiring is Woodcock's reading of the text.
* **[own]** — Woodcock's own choice. Nothing published prescribes it; the reason
  is given.

Sources are listed in [`provenance.md`](provenance.md). Abbreviations:
EAGLE = arXiv:2401.15077, EAGLE-2 = arXiv:2406.16858, EAGLE-3 = arXiv:2503.01840,
EAGLE-3.1 = "Attention Drift", arXiv:2605.09992 (CC BY 4.0),
Osprey = arXiv:2609.09338 (CC BY 4.0).

## 1. What the drafter is

Speculative decoding lets a small model propose several next tokens and lets the
large ("target") model check all of them in one forward pass. A *hidden-state
drafter* (EAGLE family) is not an independent small language model: it reads the
target's own internal activations and is a single transformer layer plus an LM
head, so it is cheap and well aligned with the target.

## 2. Drafter architecture

| Element | In Woodcock | Basis |
|---|---|---|
| Hidden-state conditioning: drafter predicts from target features plus the token sequence advanced by one step | entry *i* gets token x_{i+1} and the target feature at position *i* | [pub] EAGLE §3.1 ("token sequence ... advanced by one time step") |
| Fusion of low, middle and high target layers by concatenation and one FC layer | `Drafter.fuse`: `FC([f_low; f_mid; f_high])`, 3·d_t → d | [pub] EAGLE-3 §3.1 |
| Which layers are low / mid / high | blocks (2, L/2, L−3), i.e. (2, 14, 25) for Qwen3-1.7B | [own] — EAGLE-3 does not give indices (`target.default_feature_layers`) |
| Separate RMSNorm on each tapped hidden state before fusion | `feature_norms` | [pub] EAGLE-3.1 §4.1 (Observation 2) and §5 |
| One decoder layer | `num_layers = 1`, attention and FFN shaped like the target's layers | [pub] EAGLE-3 §3.1, §3.2 ("a single layer decoder") ; target shapes [own] |
| Layer input = hidden state and token embedding combined; Q/K/V computed from the combination | `QKV = W_main·RMS(h) + W_aux·RMS(e(x))` | [pub, reading] EAGLE-3.1 App. A: the layer input "is the concatenation of the two" and Q/K/V "operate on x as in standard Llama". A linear map of a concatenation equals the sum of two linear maps, so Woodcock's two projections are the same function class. Normalising each stream separately before combining is [own]; App. A does not say how the streams are normalised. |
| Residual stream starts at the fused feature g (not at the concatenation) | `_streams` returns `feat` as residual | [own] — App. A does not describe the residual stream; starting from g keeps the residual at width d |
| Attention gate before W_O (EAGLE-3.1 App. A) | **not implemented** | — (possible future ablation) |
| Post-norm: the RMSNorm output is both the LM-head input and the feature fed to the next draft step | `post_norm=True`, `Drafter.feedback` | [pub, reading] EAGLE-3.1 §4.2 ("post-normalization to the drafter hidden state between speculation steps prevents residual-scale accumulation"); the exact wiring (same normalised vector to head and feedback) is Woodcock's reading |
| q/k RMSNorm, RoPE, SwiGLU FFN | as in the target's Qwen3 layers | [own] — copies the target's layer type |
| Optional sliding-window attention in the drafter | `window` (off by default) | [pub] EAGLE-3.1 §5.2 uses SWA as a long-context evaluation tool, not as a proposed method; in Woodcock it is an option, off for all trained drafters |
| Token embedding copied from the target and frozen | `init_from_target`, `train_embeddings=False` | [pub] EAGLE §3.1 ("Embedding layer and LM Head employ the parameters of the target LLM") |
| LM head copied from the target, then **trained** | `train_head=True` | [own] — EAGLE §3.1 keeps the target's head frozen; EAGLE-3 §3.1 trains its own head (EAGLE-3.1 §3 notes EAGLE-3 is trained "with its own LM head"); copying the target's head as the initial value follows Osprey App. C (drafters "inherit ... the LM head verbatim") |
| Full-vocabulary LM head (151,936 rows for Qwen3) | `lm_head` | inherited from the target; its cost is the subject of [`design-vocab-trim.md`](design-vocab-trim.md) |
| Decoder layer randomly initialised (or, for ablation, copied from the target's last layer) | `init: scratch` / `layerinit` | [own] |

## 3. Training

| Element | In Woodcock | Basis |
|---|---|---|
| Training data = responses regenerated by the target itself | `woodcock regen` (T=0.7, top-p 0.8, top-k 20, ≤512 tokens, non-thinking chat template) | [pub] EAGLE-3.1 App. C trains on data "with regenerated answers using target model"; sampling settings [own] |
| Prompt sources (UltraChat, Magicoder-OSS, GSM8K, Aya) | `woodcock prompts` | [own], chosen for licence (provenance §5) |
| Training-time test (TTT): the drafter is unrolled on its own outputs during training, with "diagonal" masks for the simulated steps | `Drafter.ttt_forward`, `_ttt_attention` | [pub] EAGLE-3 §3.2 and its Fig. 6 ("All attention masks are diagonal, except when the original training data is used as the key") |
| TTT depth 4 | `ttt_steps: 4` | [pub] EAGLE-3.1 §5 ("reduce the TTT length from 8 to 4") with post-norm |
| No feature-regression loss; only token prediction | `ttt_loss` | [pub] EAGLE-3 §1 and §3.2 ("remove the feature prediction constraint") |
| Loss = soft-label cross-entropy to the target's distribution (forward KL up to a constant) | `soft_ce_step` | [own] — EAGLE-3 does not name its loss. SlimSpec (arXiv:2605.10453 §5.2) trains EAGLE-3-style drafters with a "standard KL-divergence loss", which has the same gradient |
| Per-step weights λ^j, λ = 0.8 | `step_discount` | [pub] Osprey §3.4, Eq. 5 ("discounted distillation loss") |
| Loss on assistant (response) tokens only | `SFTStream`, `target_pass_for` | [pub] EAGLE-3.1 §5.1 ("the loss is computed only on assistant tokens") |
| EOS appended only to responses that ended naturally | `SFTStream.examples` | [own] (responses cut at the cap would otherwise teach a false EOS) |
| Target forward online (features not stored) | `target_pass_for` | [own] — storing 3 taps costs ~12 KB/token for Qwen3-1.7B |
| Heads and soft-CE evaluated only on supervised rows; `mx.checkpoint` around the vocabulary-sized CE | `ttt_loss` | [own], memory/compute engineering; equality with the masked full loss is tested |
| bf16 compute with fp32 master weights | `MasterWeights` | [own] standard mixed-precision practice; tested (`test_master_weights_keep_updates_bf16_would_drop`) |
| AdamW (β = 0.9, 0.95), warm-up + cosine, clip 0.5, grad accumulation, token-budget batching | `adapt` | [own] hyper-parameters |

## 4. Decoding

| Element | In Woodcock | Basis |
|---|---|---|
| Chain verification at T > 0: accept with min(1, p/q), resample from norm([p − q]+) | `verify_chain_stochastic` | [pub] arXiv:2211.17192 §2.3, Alg. 1 (proof App. A.1); arXiv:2302.01318 ("modified rejection sampling scheme", abstract) |
| Tree verification at T > 0, children drawn without replacement, recursive rejection | `verify_tree_stochastic` | [pub] arXiv:2402.14160 |
| Greedy verification: longest prefix equal to the target's argmax, plus one target token | `verify_tree_greedy`, `_fused_chain_round` | [pub] EAGLE §3.3 (tree attention); greedy rule is the T→0 case of speculative sampling |
| Tree verified in one target forward with a tree attention mask and depth positions | `tree_attention_mask`, `Target.__call__(positions, mask)` | [pub] EAGLE §3.3 |
| Static tree: expand the top nodes of each level by path probability; verify the top-N nodes by path probability | `StaticPolicy`, `_top_by_phat` | [pub] EAGLE-2 §4.1 (expansion by "global acceptance probabilities") and §4.2 (reranking "top m tokens"); EAGLE-2 §3.2 justifies draft confidence as an acceptance estimate |
| At T > 0 the number of children is fixed before drawing; no drawn node is pruned by its own probability | `Plan.children_for` | [own], derived from arXiv:2402.14160; negative controls in `tests/test_sampling.py` |
| Single-sync fused chain rounds (K draft steps, verification and argmax in one lazily evaluated MLX graph) | `_fused_chain_round` | [own] |
| KV-cache compaction after tree verification | `compact_cache` | [own] |

## 5. What is not in this code base

The earlier code base had a cost-aware draft-size policy and a low-rank
candidate-retrieval LM head; both were removed ([`CARRYOVER.md`](../CARRYOVER.md)).
Drafting-cost reductions are now specified from public sources only, in
`docs/design-*.md`.
